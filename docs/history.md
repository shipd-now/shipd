# Where shipd came from

This page is my account of how shipd began. I wrote it in the first person because the story is mine. It holds two kinds of fact. The stages come from my memory. The two dates for the repositories come from their first commits.

## Asking an agent for tickets

In late July 2025, I began asking an AI coding agent for tickets. Each ticket planned one piece of work. It worked surprisingly well.

## A template for each ticket

I then wrote a template for the structure of each ticket. Only later did I learn that this practice has a name: spec-driven development. In shipd terms, each piece of planned work is a [change](what-is-shipd.md), and its requirements live in a spec.

## Skills with no name

At that stage the tools had no name and no repository. I copied the skills from one project to the next by hand. I never published them.

## Review and pull requests

Next came a review feature and a pull-request feature.

## automikk

The set of tools grew into "automikk". It was a way for me to replace my own work with automation. The automikk repository dates its first commit 2026-07-22.

I used the tools every day. I kept improving them, and I kept adding skills.

## shipd

I published the tools as shipd, at shipd.now. The shipd repository dates its first commit 2026-08-13. shipd is open source under the MIT license, so anyone can use it.
